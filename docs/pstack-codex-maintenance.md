# Maintain the PStack Codex fork

`pstack/` is the upstream workflow source. Codex also copies `cursor-team-kit/skills/deslop`, `control-cli`, and `control-ui` verbatim and bundles `cursor-team-kit/LICENSE`. Review those source directories and their license on every sync. The target registry in `scripts/generate-pstack-harness-trees.mjs` owns every file under `harness/pstack/`. Edit source files, never generated files. Codex presentation metadata is derived from `pstack/plugin.json`, including its version and original author. Keep Codex changes small so upstream merges stay reviewable.

## Sync upstream

1. Start with a clean isolated worktree on a new sync branch from the current fork main. Preserve existing user work. Fetch the fork and `https://github.com/cursor/plugins`; inspect upstream changes before merging the selected upstream revision. Record both base revisions in the PR.
2. Merge upstream without resetting history or force-pushing. Resolve source conflicts deliberately. Keep the Codex marketplace name distinct and preserve the original author. When upstream adds a runtime feature, verify its behavior before replacing the fork implementation.
3. Inspect added skills and changes to the three bundled cursor-team-kit dependencies and license, Cursor tool vocabulary, model roles, agent definitions, and runtime file reads. Update `pstack/docs/harness/codex.md` for every newly required capability and setup change. A passing vocabulary check proves term coverage, not semantic equivalence. Bundle every required runtime dependency; omitted upstream links are reference material only.
4. Run `node scripts/generate-pstack-harness-trees.mjs`, then `node scripts/generate-pstack-harness-trees.mjs --check`. Install the validation dependencies as the existing CI workflow specifies. Run `node scripts/validate-plugins.mjs`, `node --test scripts/test/*.test.mjs`, `node scripts/check-pstack-docs.mjs`, and the relevant upstream skill tests. Review generated diffs for both targets and executable modes. Claude output should change only when upstream/shared docs require it.
5. Test discovery and installation with an isolated CODEX_HOME and a disposable trusted project before touching an active installation. Confirm marketplace identity, source path, cache content, the 58 upstream skills plus three bundled dependencies at this revision, their license, the adapter pointer, model setup persistence, and absence of startup hooks. Exercise an actual workflow on the intended host; report unavailable tools/models and reduced reviewer independence. Discovery alone is insufficient evidence.
6. Open a sync PR with upstream revision, changes, test evidence, and capability limits. Obtain independent review and passing CI before merge. Keep conflicts and failed checks visible. An existing thread heartbeat may perform this procedure; there is no second GitHub sync scheduler in this fork.
7. After the verified revision merges, refresh the installed marketplace/plugin through the host, restart or open a fresh session as required, and inspect the installed cache. Recheck a skill and adapter read against the verified revision. Preserve previous installation details for rollback; avoid broad cache deletion. Stay quiet on unchanged upstream; notify on meaningful updates, conflicts, failed verification, or user action needed.

Retire the adapter only when upstream's Codex support passes the same installation and behavior checks and preserves the required workflows. A similarly named file is not evidence of compatibility.
